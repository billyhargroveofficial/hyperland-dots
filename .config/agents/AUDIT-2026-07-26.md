# Аудит системы AI-харнессов — 2026-07-26

## Исходное состояние

- Один Python-скрипт вручную преобразовывал MCP для Claude, Codex, Qwen,
  legacy Kimi, Kimi Code и OpenCode.
- Синхронизация была upsert-only: удалённый из канона сервер оставался в
  нативных конфигах.
- `${VAR}` материализовались в несколько файлов и в `*.bak-mcp-sync`.
- Backup одного файла многократно перезаписывался во время одного запуска.
- Правила раздавались симлинками, из-за чего Codex получал одинаковый
  `AGENTS.md` как global и project rule при работе из `$HOME`.
- Skills для Codex направлялись в устаревший `~/.codex/skills`.
- Grok Build не имел нативного target и неявно импортировал Claude rules/MCP.
- Qwen-only SearXNG жил вне канона.

## Исследование

- `AGENTS.md` стал переносимым форматом инструкций, но vendor-specific
  user-scope пути различаются.
- Agent Skills стандартизует каталог `<skill>/SKILL.md`.
- MCP стандартизует протокол, но не локальный registry каждого клиента.
- Portable auto-memory стандарта нет: это изменяемое runtime-состояние.
- Rulesync имеет наиболее полное покрытие текущей установки: Claude Code,
  Codex CLI, Qwen Code, Kimi Code, OpenCode и Grok Build, а также rules, MCP,
  skills, commands, subagents, hooks и permissions.

Рассмотрены Rulesync, Ruler, gaal, universal-mcp-sync, MCPM, GNU Stow, chezmoi и
Home Manager. Для текущего набора харнессов выбран Rulesync.

## Принятая архитектура

```text
~/.config/agents/
├── rulesync.jsonc
├── secrets.env
├── qwen-service.env
├── telegram-service.env
├── .rulesync/
│   ├── rules/overview.md
│   ├── mcp.jsonc
│   └── skills/
├── README.md
└── AUDIT-2026-07-26.md
```

- Rulesync `15.1.0` является schema-aware генератором.
- `mcp-sync` загружает env, запускает global generation, делает ротационный
  backup, создаёт systemd env-файлы и восстанавливает compatibility links.
- Нативные vendor-файлы — generated copies, а не цепочка симлинков.
- Shared MCP заменяет управляемый набор; tool-scoped блоки задают исключения.
- SearXNG подключён tool-scoped к Qwen и Grok.
- Для Codex используется `bearer_token_env_var`, для Kimi —
  `bearerTokenEnvVar`.
- Общая курируемая память находится в root-rule; auto-memory не синхронизируется.
- Grok получает нативные rules/MCP/skills; Claude compatibility отключена.
- `~/AGENTS.md` удалён, чтобы user-scope правило не загружалось повторно.
- Версионируемый источник и bootstrap находятся в `hyperland-dots`.

## Выявленный adapter bug

Rulesync `15.1.0` передавал shared HTTP MCP в Qwen как `type = http` + `url`.
Qwen трактует `url` как legacy SSE; streamable HTTP требует `httpUrl`.

В `.rulesync/mcp.jsonc` добавлены Qwen-specific replacements для GitHub и
Telegram с `httpUrl`.

## Grok Build

Добавлены модели:

- `kimi-k3`;
- `kimi-k3-256k`;
- `qwen-token-plan` (`qwen3.7-plus`, Responses);
- `qwen-max-token-plan` (`qwen3.8-max-preview`, Responses).

Токены берутся через `env_key`; в `config.toml` они не записаны.
`shell_environment_policy` фильтрует `*KEY*`, `*TOKEN*` и `*SECRET*` для
обычных shell-команд. Persistent login shell может повторно загрузить их из
`.zshrc`.

Реальные минимальные проверки:

| Маршрут | Результат |
| --- | --- |
| Grok → Kimi K3 | `OK`, exit `0` |
| Grok → Qwen 3.7 Plus Token Plan | `OK`, exit `0` |
| Grok → Qwen 3.8 Max Preview Token Plan | `OK`, exit `0` |

## Осознанно не изменено

- Permissive permission modes существующих харнессов.
- Постоянный `ui.yolo = true` в Grok Build включён по решению владельца.
- Qwen Telegram channel с рабочей директорией `$HOME`.
- Постоянный Chrome CDP на `127.0.0.1:9222`.
- Legacy Python Kimi CLI остаётся установленным, но не является активным `kimi`.
- Переход с файлов `600` на password manager/systemd credentials.
- Persistent login shell Grok может повторно загрузить секреты из `.zshrc`.
- Commands, subagents, hooks и permissions Rulesync не активированы пустыми
  features, чтобы не очищать существующие native-настройки.
