# waybar

## Текущая компоновка

Панель собрана из трёх визуальных островков:

- слева `group/workspaces-island` только с безымянными рабочими столами без
  иконок приложений, рядом отдельный `group/accent` с SVG-палитрой;
- по центру пять пар `image#telemetry-*` + `custom/telemetry-*` для
  CPU/GPU/RAM/VRAM/SSD;
- справа tray и единый набор SVG для сети, VPN, Bluetooth, звука, яркости,
  видеообоев, записи и питания; дата остаётся обычным текстом без очевидной иконки
  календаря, а уровень звука показывает сам слайдер без дублирующего процента.

Центральные модули печатает `scripts/telemetry.py`: рядом с SVG остаются
только значения `50°C`, `55°C`, `11/96`, `1/12`, `248/916`.
CPU берётся из `sensors`, GPU и VRAM — из `nvidia-smi`, RAM — из
`/proc/meminfo`, SSD — через `statvfs("/home")`. Установленный объём RAM
округляется до ближайшего следующего блока 8 GiB, чтобы вместо
зарезервированных ядром ~94 GiB показывать физические 96.
Пять процессов модуля не запускают `nvidia-smi` пять раз: снимок защищён
`flock` и кэшируется в `$XDG_RUNTIME_DIR/waybar-telemetry.json` на один тик.

Весь текст панели использует один `SF Pro Display` 14 px с весом `600` и
tracking `-0.1px`; локальные `bold` у часов, языка и процентов удалены.
Начертание совпадает с общим системным `SF Pro Display SemiBold`, отдельных
геометрических деформаций для Waybar нет. Nerd Font в Waybar больше не нужен.

Акцент задаётся в `accent.css`; кнопки purple/blue/teal/amber перегенерируют
CSS, SVG и приватную тему app-иконок, а соседняя SVG-кнопка вызывает общий
dark/light toggle. Hover-подсказки намеренно выключены у всех модулей. Для
tray, у которого нет настройки `tooltip: false`, остаточный GTK-tooltip
делается полностью прозрачным в CSS. SVG VPN — только индикатор; переключение
оставлено на `Alt+P`, чтобы процесс `sing-box` не становился дочерним процессом
Waybar и не обрывался при reload панели.

## Старые подробные модули CPU, памяти и диска

Скрипты подробных CPU, memory и disk сохранены для tooltip-диагностики и
возможного возврата, но их старых module entries в `config` больше нет.
Встроенные модули показывают только проценты и не умеют произвольный tooltip.

Сохранённые custom-модули устроены так:

| Модуль | Скрипт | Текст | Попап |
|---|---|---|---|
| `custom/cpu` | `scripts/cpu.py` | загрузка, `12%` | топ процессов по CPU **сейчас** + load average |
| `custom/memory` | `scripts/memory.py` | `14.4/94G` | топ процессов по RSS, кэш, swap |
| `custom/disk` | `scripts/disk.py` | `126/916G` | разбивка по разделам + крупнейшие каталоги в `~` |

Три вещи, которые в них неочевидны и которые легко сломать при правке:

**CPU считается дельтой между тиками, а не через `ps`.** `ps -eo pcpu` и первая
итерация `top -bn1` дают среднее за всё время жизни процесса: браузер,
открытый десять часов назад, вечно висел бы в топе с процентами, набранными
ночью. Скрипт запоминает `utime+stime` каждого процесса и общее время из
`/proc/stat` в `$XDG_RUNTIME_DIR`, а на следующем тике делит приращения.
Побочный эффект: первый вызов после старта процентов показать не может —
сравнивать не с чем, там стоит `…`. Проценты нормированы на ядро, как в `top`,
поэтому многопоточный процесс законно показывает больше 100%.

**У `custom/cpu` маленький `interval` (3 с) намеренно.** waybar перерисовывает
уже открытый tooltip на каждом обновлении модуля — без частого тика попап
замер бы на цифрах момента наведения.

**`du` в попапе диска не считается в горячем пути.** Обход сотни гигабайт —
десятки секунд, waybar встал бы колом на каждом тике. Результат кэшируется в
`$XDG_RUNTIME_DIR`, пересчёт уходит в фон с lock-файлом, попап всегда рисуется
мгновенно из кэша (TTL 30 мин). Флаг `-x` у `du` обязателен, иначе счёт уходит
в чужие точки монтирования.

Память считается как `MemTotal - MemAvailable`, а не через `MemFree`: `MemFree`
не учитывает кэш и буферы, которые ядро отдаёт по первому запросу, и вместо
«занято 14 из 94 ГБ» вышло бы «занято 65».

Сумма RSS по списку процессов больше, чем «занято» в заголовке — это нормально,
разделяемые страницы считаются каждому процессу. Точный ответ дал бы PSS из
`/proc/*/smaps_rollup`, но это сотни файлов на каждый тик ради вопроса «кто
больше всех», на который RSS отвечает верно.

## SVG вместо шрифтовых глифов

Waybar умеет показывать изображения штатным модулем `image`; SVG рендерит
GTK/librsvg. Исходники лежат в `icons/` и взяты из единого набора Lucide,
лицензия сохранена рядом. Все имеют сетку 24×24, stroke 2 и одинаковые
round-cap/round-join, поэтому визуальная масса больше не зависит от шрифта.

`scripts/svg-icons.sh build COLOR` заменяет `currentColor` на текущий оттенок
light/dark и кладёт готовые SVG в `~/.cache/waybar-svg-icons/`. Он же выбирает
state-иконки Wi-Fi/VPN/Bluetooth/volume/recorder и возвращает Waybar путь плюс
служебное описание состояния. Показ этого описания отключён конфигом.
`scripts/accent.sh` пересобирает SVG при выборе цвета, а
`toggle-theme.sh` — при смене светлой/тёмной темы; затем `SIGUSR2` штатно
перечитывает image-модули.

Кнопка питания — намеренное исключение: это `custom/power-button` с
`CirclePower` как центрированным CSS-фоном 16×16. Так она не участвует в
baseline/внутреннем выравнивании `GtkImage` и остаётся оптически по центру
правого острова.

Разделение `image#...` и текстового value-модуля принципиально: Pango label не
умеет вставлять произвольный SVG внутрь строки. Зато ширина и интервалы теперь
задаются обычным CSS и не зависят от advance-width приватного font glyph.

## Ручное управление видеообоями

`image#wallpaper` показывает `play.svg`, пока `nv-wallpaper.service` выключен,
и `pause.svg`, пока рендерер работает. Клик вызывает
`scripts/video-wallpaper.sh toggle`: сервис запускается или полностью
останавливается, сохраняя таймкод последнего показанного кадра. Следующий запуск
продолжается оттуда же, а модулю сразу отправляется `RTMIN+11`. Интервал 5
секунд остаётся запасным обновлением состояния, например после команды из
терминала.

Никакой проверки активного окна, автопаузы и автозапуска здесь нет. После
логина остаётся статичный фон `awww`; видео начинает играть только по клику.
При завершении Hyprland сервис корректно останавливается. `wall-next.sh` и
`wall-select.sh` тоже сначала выключают видео, поэтому выбранная картинка сразу
становится видна.

Dotfiles содержат кнопку, иконки, зависимости сборки и session hook, но не
клонируют отдельный репозиторий рендерера. При checkout в `~/nv-wallpaper` его
достаточно один раз установить от обычного пользователя:

```bash
cd ~/nv-wallpaper
./scripts/install-user.sh /absolute/path/to/video.mov DP-2,DP-3
```

Если `~/.local/bin/nv-wallpaperctl` отсутствует, клик ничего не меняет и
показывает уведомление. Статичный `awww` работает независимо и остаётся
фоновым слоем, когда видео выключено.

## Модуль с `interval: "once"` не перечитывается ничем, кроме рестарта

`custom/brightness` объявлен как `"interval": "once"` + `"signal": 9`. Если
поправить `brightness.sh`, панель продолжит показывать **старый** текст:

- `pkill -USR2 waybar` (reload конфига) — не помогает;
- `pkill -RTMIN+9 waybar` (свой сигнал модуля) — не помогает;
- помогает только полный перезапуск waybar.

Легко потерять полчаса, решив, что правка не сработала. Она сработала.

## Воркспейсы: стабильная ширина острова

GTK3 не знает ни `transform`, ни `translate`, а каждая кнопка — отдельный
виджет. Подвинуть пилюлю между кнопками нечем.

Каждая кнопка — настоящий круг 14×14 без текста. Неактивные имеют слабую
акцентную заливку и тонкое внутреннее кольцо; активный получает сплошной акцент
и внешнее полупрозрачное halo через `box-shadow`. Halo не участвует в
allocation GTK, поэтому все кнопки и внешний край острова остаются на месте.
Transition ограничен цветом, тенью и opacity вместо `all`.

Что **не** работает, хотя выглядит логично: анимировать `background-size` или
`background-position` заливки. Пилюля тогда разворачивается и схлопывается в
границах своей кнопки — визуально это масштабирование по X, а не движение.

Ширину, padding и margin нельзя добавлять в `transition`: подсветка может
плавно перетекать, но геометрия группы должна оставаться постоянной.

Цифры и иконки приложений рабочих столов намеренно скрыты: кнопки показывают
только состояние пустой/активной пилюли. Генератор
`~/.local/bin/waybar-mono-icons` всё ещё нужен для подменённых tray-иконок и
автоматически обновляется через `scripts/accent.sh` при смене цвета.

Tray передаёт готовые PNG/pixmap от самих приложений, поэтому обычный CSS
`color` их не перекрашивает. Текущие Telegram, NetworkManager и Flov
переопределены штатным объектом `tray.icons`: генератор публикует их версии как
`waybar-tray-{telegram,network,flov}` в пользовательский GTK icon path. При
смене акцента файлы пересобираются вместе с иконками рабочих столов; клики и
контекстные меню остаются родными StatusNotifierItem.

## Проверять анимацию скриншотами нельзя

`grim` тратит на кадр больше 100 мс и стабильно не попадает в анимацию
длиной 260 мс — все кадры выходят уже финальные. Записывать надо видео и
разбирать его покадрово:

```bash
wf-recorder -g "1130,0 360x45" -f /tmp/ws.mp4 -r 60 -c libx264 -x yuv420p &
# ... переключить воркспейсы ...
kill -INT %1
ffmpeg -i /tmp/ws.mp4 -vf fps=30 /tmp/frames/f%03d.png
```

Кодек здесь именно `libx264`: NVENC отказывается кодировать кадр такого
размера, см. [screen-recording.md](screen-recording.md).
