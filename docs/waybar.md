# waybar

## Текущая компоновка

Панель собрана из трёх визуальных островков:

- слева `group/workspaces-island` с безымянными рабочими столами и иконками
  запущенных приложений, рядом отдельный `group/accent`;
- по центру `custom/telemetry` одной строкой без пиктограмм;
- справа tray, сеть, VPN, раскладка, Bluetooth, звук, яркость, часы и питание.

Центральную строку печатает `scripts/telemetry.py` в формате
`cpu: 50°C gpu: 55°C | ram: 11/96 vram: 1/12 | ssd: 248/916`.
CPU берётся из `sensors`, GPU и VRAM — из `nvidia-smi`, RAM — из
`/proc/meminfo`, SSD — через `statvfs("/home")`. Точные значения доступны в
tooltip. Установленный объём RAM округляется до ближайшего следующего блока
8 GiB, чтобы вместо зарезервированных ядром ~94 GiB показывать физические 96.

Шрифт интерфейса — `Inter Variable` с запасным `JetBrainsMono Nerd Font` для
символов. Акцент задаётся в `accent.css`; кнопки purple/blue/teal/amber
перегенерируют CSS и приватную тему иконок, а соседняя кнопка вызывает общий
dark/light toggle.

## Старые подробные модули CPU, памяти и диска

Скрипты подробных `custom/cpu`, `custom/memory` и `custom/disk` сохранены для
tooltip-диагностики и возможного возврата, но в текущие `modules-*` не входят.
Встроенные модули показывают только проценты и не умеют произвольный tooltip.

Сохранённые custom-модули устроены так:

| Модуль | Скрипт | Текст | Попап |
|---|---|---|---|
| `custom/cpu` | `scripts/cpu.py` | загрузка, `12%` | топ процессов по CPU **сейчас** + load average |
| `custom/memory` | `scripts/memory.py` | `14.4/94G` | топ процессов по RSS, кэш, swap |
| `custom/disk` | `scripts/disk.py` | `126/916G` | разбивка по разделам + крупнейшие каталоги в `~` |

Три вещи, которые в них неочевидны и которые легко сломать при правке:

**CPU считается дельтой между тиками, а не через `ps`.** `ps -eo pcpu` и первая
итерация `top -bn1` дают среднее за всё время жизни процесса: браузер,
открытый десять часов назад, вечно висел бы в топе с процентами, набранными
ночью. Скрипт запоминает `utime+stime` каждого процесса и общее время из
`/proc/stat` в `$XDG_RUNTIME_DIR`, а на следующем тике делит приращения.
Побочный эффект: первый вызов после старта процентов показать не может —
сравнивать не с чем, там стоит `…`. Проценты нормированы на ядро, как в `top`,
поэтому многопоточный процесс законно показывает больше 100%.

**У `custom/cpu` маленький `interval` (3 с) намеренно.** waybar перерисовывает
уже открытый tooltip на каждом обновлении модуля — без частого тика попап
замер бы на цифрах момента наведения.

**`du` в попапе диска не считается в горячем пути.** Обход сотни гигабайт —
десятки секунд, waybar встал бы колом на каждом тике. Результат кэшируется в
`$XDG_RUNTIME_DIR`, пересчёт уходит в фон с lock-файлом, попап всегда рисуется
мгновенно из кэша (TTL 30 мин). Флаг `-x` у `du` обязателен, иначе счёт уходит
в чужие точки монтирования.

Память считается как `MemTotal - MemAvailable`, а не через `MemFree`: `MemFree`
не учитывает кэш и буферы, которые ядро отдаёт по первому запросу, и вместо
«занято 14 из 94 ГБ» вышло бы «занято 65».

Сумма RSS по списку процессов больше, чем «занято» в заголовке — это нормально,
разделяемые страницы считаются каждому процессу. Точный ответ дал бы PSS из
`/proc/*/smaps_rollup`, но это сотни файлов на каждый тик ради вопроса «кто
больше всех», на который RSS отвечает верно.

## Иконка и текст слипаются, хотя пробел в конфиге есть

Симптом: в панели `4.66%` прижато вплотную к иконке, при этом в `config`
написано `"format": "󰻠 {}%"` — пробел на месте.

Причина не в конфиге. Глифы Nerd Font из приватной области (`U+F0000+`)
рисуются **шире своей ячейки** и наезжают на следующий символ, съедая
одиночный пробел. Между обычными буквами тот же пробел виден нормально —
поэтому `3566 RPM` выглядит правильно, а `󰈐3566` нет.

Проверять глазами в терминале бесполезно: широкий глиф занимает две колонки, и
вторая выглядит как пробел, которого в файле нет. Смотреть надо коды символов:

```bash
python3 -c "
import json
cfg = json.load(open('$HOME/.config/waybar/config'))
s = cfg['cpu']['format']
print(''.join(f'[U+{ord(c):X}]' if ord(c) > 0xE000 else ('␣' if c == ' ' else c) for c in s))"
```

**Решение — два пробела после иконки.** Не опечатка, менять на один нельзя.
Для самых широких глифов нужно три: солнце яркости `U+F00E0` и веер wifi
`U+F0928` — замер по скриншоту давал у них 2–3 px зазора там, где у соседей
было 4–6 px.

Двойной пробел стоит не только в `config`, но и в скриптах, которые сами
отдают JSON: `waybar/scripts/singbox-status.sh`, `waybar/scripts/recorder.sh`,
`hypr/scripts/brightness.sh`.

Измерить зазор объективно можно так: снять панель `grim`, развернуть в
rawvideo через ffmpeg и посчитать столбцы без «чернил» между группами
символов.

## Модуль с `interval: "once"` не перечитывается ничем, кроме рестарта

`custom/brightness` объявлен как `"interval": "once"` + `"signal": 9`. Если
поправить `brightness.sh`, панель продолжит показывать **старый** текст:

- `pkill -USR2 waybar` (reload конфига) — не помогает;
- `pkill -RTMIN+9 waybar` (свой сигнал модуля) — не помогает;
- помогает только полный перезапуск waybar.

Легко потерять полчаса, решив, что правка не сработала. Она сработала.

## CSS-анимация в модуле сбрасывается на каждом обновлении

waybar на каждом обновлении custom-модуля снимает и заново вешает CSS-класс, а
это перезапускает анимацию с нуля. При `interval: 2` анимация длиной 1 с
никогда не доигрывала и выглядела застывшей.

**Правило: если у модуля есть анимация, `interval` должен быть заметно больше
её длительности.** У рекордера стоит `interval: 30` плюс мгновенное обновление
сигналом `RTMIN+10` из самого скрипта — реакция на клик при этом остаётся
немедленной, а анимация не рвётся.

## Анимировать `opacity` в GTK3 бесполезно

GTK3 гасит непрозрачность виджета целиком, не перерисовывая метку — анимация
есть, а визуально ничего не происходит. Мигание рекордера сделано через
`@keyframes` по `color`, и только так оно работает.

## Воркспейсы: переезд выделения

GTK3 не знает ни `transform`, ни `translate`, а каждая кнопка — отдельный
виджет. Подвинуть пилюлю между кнопками нечем.

Рабочий приём (так делают и `prasanthrangan/hyprdots`, и
`JaKooLit/Hyprland-Dots`): заливка есть у **всех** кнопок постоянно, просто
приглушённая через `opacity`, а активная становится яркой и **шире** через
`min-width`. Соседние кнопки при этом физически разъезжаются — двигаются сами
виджеты, и это читается как переезд выделения.

Что **не** работает, хотя выглядит логично: анимировать `background-size` или
`background-position` заливки. Пилюля тогда разворачивается и схлопывается в
границах своей кнопки — визуально это масштабирование по X, а не движение.

В оригинале у обоих наборов стоит пружинная кривая
`cubic-bezier(.55, -0.68, .48, 1.682)` — значения вне `[0,1]` дают отскок в
конце. Здесь она заменена на `cubic-bezier(0.4, 0, 0.2, 1)` намеренно:
движение должно быть гладким, без перелёта.

Цифры рабочих столов намеренно скрыты. `workspace-taskbar` выводит приложения
внутри каждой кнопки, а тема `WaybarMono` заставляет Waybar брать обработанные
одноцветные силуэты. Генератор `~/.local/bin/waybar-mono-icons` находит иконки
из desktop-файлов, приводит их к grayscale и тонирует выбранным акцентом через
ImageMagick. `scripts/accent.sh` автоматически запускает генератор при смене
цвета; результат и GTK icon cache остаются локальными и в Git не входят.

## Проверять анимацию скриншотами нельзя

`grim` тратит на кадр больше 100 мс и стабильно не попадает в анимацию
длиной 260 мс — все кадры выходят уже финальные. Записывать надо видео и
разбирать его покадрово:

```bash
wf-recorder -g "1130,0 360x45" -f /tmp/ws.mp4 -r 60 -c libx264 -x yuv420p &
# ... переключить воркспейсы ...
kill -INT %1
ffmpeg -i /tmp/ws.mp4 -vf fps=30 /tmp/frames/f%03d.png
```

Кодек здесь именно `libx264`: NVENC отказывается кодировать кадр такого
размера, см. [screen-recording.md](screen-recording.md).
