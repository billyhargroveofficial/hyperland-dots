# Нейтральный AI control plane

Dotfiles содержат только стартовую структуру Rulesync. Фактический набор
харнессов, MCP-серверов и target-specific исправлений живёт локально в
`~/.config/agents/` и не синхронизируется обратно в репозиторий.

## Безопасная инициализация

```bash
./scripts/install-ai-harnesses.sh
```

Bootstrap копирует только отсутствующие файлы. Он не перезаписывает локальный
control plane, не ставит и не удаляет vendor CLI, не меняет фоновые сервисы и
не запускает генерацию автоматически.

## Локальный цикл изменений

```bash
mcp-sync --list-targets
mcp-sync --dry-run
mcp-sync
mcp-sync --check
```

`--list-targets` читает текущий локальный `rulesync.jsonc`, поэтому документация
не обязана знать ни имена, ни количество активных клиентов.

`--check` доказывает только отсутствие дрейфа с точки зрения Rulesync. Живость
подключений, авторизацию и чтение сгенерированных файлов нужно дополнительно
проверять штатными командами каждого локально настроенного клиента.

## Границы шаблона

- Общие правила, MCP и skills можно хранить в `.rulesync/`.
- Target-specific блоки допустимы только в локальной копии.
- Секреты находятся в `secrets.env`, который исключён из Git.
- OAuth, сессии, history, runtime-memory и сгенерированные vendor-конфиги не
  являются dotfiles.
- Vendor-specific post-processing и сервисы не входят в универсальную обёртку
  `mcp-sync`.

Пустые `targets` и `mcpServers` в репозитории — намеренная болванка. Они не
описывают состояние текущего компьютера.
